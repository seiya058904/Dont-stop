# 01 产品决策、保留项与范围

## A. 用户已经明确的决策

1. 唯一开发目标是 TowDownGame 的迭代副本；原本移动、部分枪械尤其激光枪、美术和基本爽感已经得到认可。
2. 缺点主要是内容薄：枪、怪、关卡、配件和天赋不够丰富；购买升级后，不容易知道拥有了什么、装在哪里、提升了什么。
3. 走偏爽快的动作射击方向，不走更硬核、更压抑、更难辨认的生存方向。可以有挑战，但不能把“更好”解释为“更难”。
4. 解除妨碍战场识别的局部照明/迷雾式视野限制；不因扩大视野而全部推翻原美术。
5. 保留营地整备、战斗、回营地的结构。
6. 仍然用金币购买装备；天赋也应支持金币购买。试玩版金币、天赋点以 9999 起步，优先方便体验，不做经济稀缺和平衡。
7. `Godot-GameTemplate` 是首要的打击感、爽感和玩家反馈参考；`Barren-Game` 是次要参考。不能把前者只当架构教程。
8. 不是正式发行版，是提供给用户体验并可分享的试玩/开发预览版本。

## B. 本计划补齐的执行默认

这些默认用于让 Codex 能执行，而不是无限追问。未来用户明确修改时，以新要求为准。

- 平台：Windows x64、键盘鼠标、中文界面优先。暂不做 Web/Android 适配，不牺牲现有渲染效果去迁就未要求的平台。
- 世界观与美术：延续现有像素风、角色视角和科幻武器混搭；不移植 Project Outpost 的写实顶视素材规范，也不导入归档项目需求。
- 武器：保留现有10个注册项及其特色，扩展到24把；重构不得把不同枪统一成同一个子弹模板的换皮。
- 配件：24种总目标；允许同型号多份物品用于不同枪，必须分清物品类型ID和实例ID。
- 天赋：24种持久条目目标，等级有上限；只起一次作用的消耗品另列。
- 敌人：12种普通/特殊行为角色，另有3个Boss，不以调色/加血计算新品种。
- 战斗组织：6个区域，每区5个遭遇，共30轮；第10/20/30轮作为Boss遭遇，其余轮仍有不同敌群节奏。每一轮结束都返回营地。
- 试玩可访问性：营地有明确的“试玩关卡选择”，已制作的区域均可直接试；默认继续入口仍按1–30轮推进。不要另造一个完整沙盒产品。
- 失败：保留现有复活/返回营地逻辑的宽容性质；失败不清空已买装备/天赋，不强制整个30轮重开。
- 保存：只需要可靠的营地快照与设置保存；中途退出战斗后回营地，重新开始未完成遭遇。暂不做逐帧战斗快照。
- 第一交付：M0–M2 的可玩切片；完整数量在后续里程碑完成，阶段间保留真人门。

## C. 9999 的精确定义

新增或复用一个集中式体验配置，例如 `game/config/DemoConfig.gd` 或 `.tres`。名称可适配现有代码，不为此做配置框架。

```text
build_profile = "experience_demo"
initial_gold = 9999
initial_talent_points = 9999
talent_gold_purchase_enabled = true
demo_stage_selection_enabled = true
```

创建新试玩档时设置这两个钱包余额；加载有效存档时加载已有余额，不每帧重写。购买正常扣除所选货币，击杀/通关奖励正常增加。因此9999是充裕试玩资金，不是实现数学无穷的特殊数值类型。

营地提供一个明确标注“试玩补充资源”的按钮，将这两种余额各自补到至少9999（不降低高于9999的余额）。该按钮不重置装备、天赋、关卡、音量或其他设置；需要完全重置时用另一个有确认的入口。

天赋购买明确提供“金币购买”与“天赋点升级”两种动作，默认价格金币100/级、点数1/级；不同时扣两种货币，不自动把点数兑换成金币。等级已满、条件不符、交易未完成不得扣费。

新增枪械价格可按100/150/200/250几档组织，全部新增枪总价不超过一个9999初始钱包；配件统一20/40/60几档。原有价格先保留。价格只是试玩操作反馈，不作为当前强度平衡工具。

9999不用于生命、伤害、移速、射速、敌人数、弹匣容量、叠加层数和渲染预算。保留战斗节奏以及枪械的换弹特色。暂不擅自把备弹改成无限；沿用营地补弹，但增加一次补充一整批的便利操作，避免连点几十次。

## D. 禁止的范围膨胀

不做联机、账号、排行榜、付费、成就平台、长期运营、刷取经济、永久养成树、开放世界、全面程序化地图、新引擎、ECS全面改造、云存档或全新角色阵容。

不默认添加强全屏闪光、持续抖动、所有枪都强制击退玩家、无法跳过的剧情。音乐保留但分轨可调，不能从其他项目记忆中推断用户要求本游戏无音乐。

不做全面美术重制；新增内容首先利用现有可用素材，通过合理组合、动画、轮廓差异和局部新资源保持一致性。仅调色的枪或怪不能计作机制新品种。

## E. 保留基线

记录移动速度、冲刺长度/时长、停止响应、碰撞轮廓、鼠标指向和代表枪的开火/装填参数。除了确证Bug和用户不喜欢的视野限制，不主动更改这些基线。

`BoomBoi.gd` 是已检查到的射线激光实现；用户喜欢的“激光枪”应在本地试玩时对照确认，而不是仅凭名字断言是哪一把。现有能量枪都纳入基线保护。

任何必要的手感调整要独立成提交，附旧/新数据与理由；不能藏在内容扩展提交里。不得为新枪显得强而先削弱全部旧枪。
