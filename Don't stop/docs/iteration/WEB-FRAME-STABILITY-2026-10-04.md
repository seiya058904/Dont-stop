# Web 战斗帧时间：局部物理优化与验证（2026-10-04）

基线：`0248e608fc3da97f055537086c84a66aed3efd61`。本地候选分支：`codex/web-frame-stability`；交付 manifest 记录最终提交和产物哈希。未推送、合并或部署。

## 判定

确认了一项可重复的物理热点成本下降；**不能宣称整体性能升级已经完成**。前段 4K P 三对样本中，`move_and_slide()` 每次调用累计均值从 **20.772→18.498 μs（-10.9%）**，P99 从 **26.8→23.9 ms**，平均 FPS 从 **59.36→59.62**。平均帧率接近同步上限，变化有限。

后段 4K P 两对 ABBA 中，基线/候选 P95 为 **40.5→20.1 ms**，P99 为 **70.8→22.2 ms**，FPS 为 **48.47→59.95**，>100 ms 为 **18→0**。这一组改善明显，但前后基线波动很大，不能把这一组的全部差值当作可在任何环境复现的代码收益。

最终候选的 6 份 4K P 验收样本均达到 P95≤33.3 / P99≤50 ms；>100 ms 稳态帧共 0。D 场景和共享机器上的时间波动仍须保留为开放项，不能用早期达标样本代替全部结果。

## 热点、反证与局限

- 90 秒诊断约 91 万次移动调用，约 83.7% 返回碰撞；移动累计约 18.3 秒，远高于标签更新 0.238 秒、敌弹 step 0.079 秒等已测作用域。计时是含调度干扰的作用域墙钟；包含关系不能相加当总 CPU 时间。release WASM 缺少完整原生符号，未给出精确 malloc/物理内核逐函数分摊。
- [Godot 4.7.2 的形状更新](https://github.com/godotengine/godot/blob/4.7.2-stable/modules/godot_physics_2d/godot_collision_object_2d.cpp#L162)只对 disabled shape 跳过空间索引更新；关闭 monitoring 本身没有这一效果。未修改引擎。
- 逐帧诊断的 ≤25 ms 帧平均 1.00 个物理步、移动 3.27 ms；>100 ms 帧平均 6.78 步、移动 37.62 ms。说明补帧会放大碰撞成本，**不证明最初停顿由碰撞单独引起**；该带计时器样本 P99=106.1 ms，独立保留，未充当验收或收益数字。
- A* 清空两次诊断均为 18 次，累计 4.9/5.9 ms、单次约 0.2–0.6 ms；没有持续、独立的尾帧触发对应关系。未改缓存淘汰策略。其后 cache miss 仍计入原路径成本，不据直接 clear 耗时宣称所有 miss 免费。
- Chromium trace 捕获前 53.05 秒战斗后缓冲耗尽。此窗口主线程 RAF 回调累计 40.61 秒、GPU 服务线程 WebGL 15.91 秒（并行且不是 GPU 硬件时长）；MinorGC 累计 47.23 ms、最大 6.25 ms。shader 等待大部分在启动；已捕获战斗仍有约 16.8 ms 等待。不能据这个有限窗口排除后半程所有 GPU/GC 问题。
- 无收益实验：进一步释放闲置 Area2D 节点，4K P 单次 P95/P99=20.5/27.6 ms，移动 18.72 μs/次，没有超过保留节点方案的证据；已回退。没有把节点数下降当成帧率收益。
- 1080p 的共享环境样本同样出现较慢帧；不能把所有差距归因于像素填充，也不能把当前环境波动包装成代码提升。
