## 实际改动

1. 敌弹每个物理子步仍执行寿命、扫掠、玩家命中及墙面反射；只在显示帧提交最后一份轨迹/雾提示。固定弹体绘制保留，轨迹局部坐标未变化时复用命令。没有跳过物理步、降伤害频率、缩短寿命或删除弹体。
2. 血条端点变换到共享局部空间，连续同宽段合批，保留顺序和巨型尺度；非均匀/斜切保留原绘制回退。雾上线段只合并相邻同宽段，保留 AA 和必要预警。后者局部收益可测，整场独立收益未证实。
3. 修正原预热 alpha 低于引擎可绘制阈值及世界原点不在镜头内的问题：现有准备阶段内以受光屏幕空间绘制，并预热实际 Hero GPU 粒子。CDP 曾直接记录 Boss 首次移动的两段约586ms shader等待；修复后完整 Boss 实战另测。
4. ArenaVisibility 缓存验证当前父节点、树成员和待删除状态；Hazard 的 B04 查询从全 transient 集合缩至实际 boss_ultimate 组。不改变危险边界。
5. 死亡缩放/延迟释放改为绑定节点的 Tween，保留0.5秒死亡时长；近战动画完成改为连接与状态位，避免节点删除后悬挂等待。
6. 修复 B04 大招安全窗仍继承已排队有限波次的问题：取消旧 owner 攻击及待发波次，保留已实现的 continuous source 暂停/恢复，取消量继续计账。修复前测试6通过/3失败，修复后9/9。

7. 出生选点缓存同一中心/玩家位置/半径/方向的几何筛选和世界坐标；每次仍查询动态占位与可达性，保留随机消费顺序。48个出生的选点耗时三批从26.7/31.5/21.3ms变为18.4/17.1/21.4ms；第三批收益很小，不宣称消除所有补怪长帧。121项同世界、同seed、巨型/普通、运动/出生失效及下一随机数回归通过。

## 已完成的归因与不能声称的结论

180弹下原 `_draw` 会被多个物理子步反复重建。详细样本约8秒中有86,128次绘制包装调用；保留绘制后降至显示更新量级。最终必须以轻量同源表为准。

保留绘制后的 P trace 中，12秒窗口 WebGL 同步 GetBooleanv 累计约2.76秒，GPU命令线程 CPU 约4.82秒；这些范围可能重叠，不能合计为总耗时或 GPU 毫秒。原生 GPU profiler 只用于诊断。Web GPU 执行时间 N/A。

真实隔离试验分别隐藏弹体、本体、雾层、VFX；各自改善不足以解释全部剩余预算，因此没有交付隐藏效果版。共享小网格、怪物装饰 dirty 缓存未显示稳定整场收益，已撤回。未改 HitFlash shader、物理频率、默认后端或透明排序。

早期 `--stress-iso=` 存在少取一个字符的解析错误：所有修复前隔离结果作废。native profiler 曾出现采样 Dictionary 转 int 错误和容量夹具转场后访问失效 arena，均修驱动后另测；这些详细样本不能充当正式通过证据。Web debug template 缺失，未安装新模板；release `--profiling` 无可用脚本函数表，采用原生局部 scope/CDP/单变量验证。
